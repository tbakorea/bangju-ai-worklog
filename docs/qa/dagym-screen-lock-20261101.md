# 다짐 화면 잠금 대응

## 적용

- 운영 수집기는 Application Support에 설치된 LaunchAgent와 전용 Chrome(9233)을 사용한다. 창 클릭·전면 배치를 사용하지 않는다.
- 업로드 인증용 키체인 읽기를 5초로 제한했다. 잠긴 키체인이나 승인 창 때문에 전체 작업이 무한 대기하지 않으며 인증 접근 실패는 성공으로 기록하지 않는다.
- 읽기 전용 dry-run에서는 업로드 인증 키체인을 읽지 않는다.
- 강제 검증은 이전 날짜의 업로드 완료 사본을 재사용하지 않고 새로 수집한다.
- `dagym-locked-qa.py`는 OS의 `IOConsoleLocked`를 확인하고 전체 수집 과정에서 잠금이 유지됐는지 검증한다. 이전 성공 응답만으로는 통과하지 않으며, 이번 실행 이후의 일일 서버 저장과 PT 저장 확인을 요구한다. 화면 잠금을 해제하거나 인증·절전 설정을 변경하지 않는다.

## 확인

- Python 잠금 검증 테스트 5건 통과: 알 수 없는 잠금 상태, 실제 OS 잠금 플래그, 도중 잠금 해제, 오래된 저장 응답, 새 서버 저장 확인.
- 기존 다짐·보강 Node 테스트 19건 통과.
- 정적 QA, 100명 × 90일 운영 시뮬레이션, shell 구문 검사와 diff 검사 통과.
- 전체 브라우저 QA는 기존 `representative fitness view should load Kim Young-chae's profile-user worklog`에서 중단. 이번 변경에는 직원 UI 수정이 없다.

첫 운영 잠금 검증은 `screenRemainedLocked=false`, `collectorExitCode=1`로 실패했다. 이를 잠금 수집 성공으로 보고하지 않았다. 사용자가 키체인의 최초 접근 승인 창에서 '항상 허용'을 누르지 못하고 있어 시스템 인증은 직접 처리가 필요하다. 보호된 SecurityAgent 창은 도구의 안전 제한으로 조작하지 않는다. 재검증기는 잠금 시작을 기다리도록 준비했다.

화면 잠금과 로그아웃·전원 종료는 다르다. 사용자 로그인 세션·전원·네트워크·정상 다짐 인증 및 승인된 키체인 접근이 운영 전제다. 로그인 만료 시 키체인 권한 승인이 완료되어야 자동 재로그인할 수 있다.

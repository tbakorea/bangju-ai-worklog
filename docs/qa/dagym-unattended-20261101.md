# 다짐 무인 수집 보강 검증 (2026-11-01)

## 변경

전용 프로필·로컬 포트(9233)를 유지하면서 새 브라우저를 headless로 실행한다. 전면 창 포커스는 사용하지 않는다. 정상 완료된 날짜는 재조회하지 않고 미완료일만 매시간 보완한다. 월이 바뀌는 날에는 전날이 속한 달의 PT 원장을 수집한다.

수집 전에 센터 API의 인증·센터 ID를 확인한다. 인증이 만료된 대시보드 껍데기(403 응답)를 정상 자료로 처리하지 않는다. 만료 시 신뢰한 다짐 로그인 주소에만 저장된 계정을 입력한다. 사용자 승인으로 로컬 키체인 전용 항목을 준비했으며 인증값은 소스·로그·파일에 넣지 않는다. 추가 인증·접근 승인·실패한 로그인은 직접 확인이 필요하고 비밀번호 제출 실패는 24시간 반복하지 않는다.

PT 실패가 일일 운영자료 저장을 막지 않는다. 날짜별 검증 집계를 보존해 서버 저장만 실패한 건은 포털을 다시 읽지 않고 재전송한다. 일일 저장 응답의 날짜와 PT 저장 응답의 월·전체 건수·완료 여부를 함께 확인해야 마지막 완료 날짜를 갱신한다. dry-run과 검증 실패는 기존 정상 감사 기록을 덮어쓰지 않는다.

## 검증 결과

- 다짐 관련 Node 테스트 18건 통과: 로그인 복구·외부 주소 차단·잘못된 센터 차단·403 화면·실패 반복 제한·자동완성·추가 인증·키체인 미연결·0/누락값 구분·서버 날짜/월/건수·PT 실패 시 일일 저장·재전송 응답 날짜 검증.
- `./scripts/qa-check.sh` 통과. 기존 100명 × 90일 운영 시뮬레이션 포함.
- `./scripts/mobile-browser-qa.sh`는 기존 `representative fitness view should load Kim Young-chae's profile-user worklog`에서 중단. 이번 변경에는 화면 수정이 없다.
- `bash -n`과 `git diff --check` 통과.
- 운영 LaunchAgent의 시간당 재시도 및 headless 실행 적용을 확인했다. 다른 Chrome 프로필·인증정보를 복사하지 않았다.

실제 계정의 재로그인·전체 서버 저장 확인은 키체인의 최초 시스템 접근 승인이 끝난 후 별도로 수행한다. 이 문서의 모의 테스트 통과를 운영 수집 성공으로 보고하지 않는다.

## 운영상 전제

Mac 전원·사용자 로그인 세션·네트워크·접근 가능한 키체인이 필요하다. 화면 잠금과 UI 포커스는 수집에 필요하지 않지만, 전원 꺼짐·로그아웃·추가 인증까지 우회하지 않는다. 이전 실패 날짜는 성공으로 소급 처리하거나 0으로 채우지 않는다.

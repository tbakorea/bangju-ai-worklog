# 다짐 자료의 운영 활용 설계

작성 기준: 2026-10-28. 이 문서는 구현 완료 목록과 후속 제품 설계를 구분한다. 아래 권한표·정정 이력 화면·보상 구조 전체가 이미 구현됐다는 뜻은 아니다.

## 목적과 사용 범위

다짐은 출석·예약·결제 사실의 원천이고 업무일지는 준비·응대·문제 해결·인수인계의 설명이다. 두 자료를 연결해 운영 문제를 해결하되 예약을 실적으로, 결석을 노쇼로, 기록 차이를 거짓말로 단정하지 않는다. 정직성·성실성 점수, 직원 공개순위, 자동 징계·급여·승진 판단을 만들지 않는다.

## 수집과 신뢰

- 한국시간 전날 마감자료: 출석은 하루, 매출은 월초~기준일 누계, 회원현황은 수집 시점, PT는 월간 원장을 구분한다. 누계 매출은 날짜별로 더하지 않는다.
- 01:05 수집 후 실패 시 04:05·07:05 보완 실행. 완료 날짜는 중복 수집하지 않는다. 맥 실행·네트워크·로그인·업로드 인증이 전제다. 무인 장비 또는 승인된 서버 수집으로 이전하기 전에는 맥 종료·로그아웃 상황의 무중단을 보장할 수 없다.
- 로그인/회원가입 화면, 기간 불일치, 필수값 누락은 실패다. 미확인은 0이 아니다. 원천 화면 날짜·수집시각·건수·서버 저장 확인을 함께 보관한다. 실패로 기존 정상자료를 덮어쓰지 않는다.
- 매일 08:30 건강 점검으로 누락·로그인 필요·복구를 확인한다. 직원 평가에 수집 장애를 반영하지 않는다.

## 경영과 운영에 연결할 의사결정

| 관찰 자료 | 활용 | 완료 확인 |
|---|---|---|
| 출석의 같은 요일·시간대 흐름 | 혼잡 시간에 안내·청결·공간 점검 배치 | 대기·불편 해결 여부를 인수인계 |
| 예약·출석·취소·결석의 구분 | 예약 확인, 변경 안내, 빈 시간 운영 개선 | 실제 상태 확정과 후속 조치 확인 |
| 만료예정과 연락 동의 | 담당자의 서비스 점검과 재등록 안내 | 동의된 연락·응답·다음 조치 기록 |
| 월 누계 매출·환불·미수금 | 대표/센터장의 현금흐름·상품 구성 판단 | 기간 일치·중복 제거·원장 대조 |
| 시설 문제·회원 요청·정정 | 매출로 드러나지 않는 운영 기여 인정 | 담당자·다음 확인일·해결 근거 |

오늘 행동은 직무·근무시간에 맞는 한두 가지로 제안하고 담당자가 선택·조정한다. 작은 표본의 증감을 개인 성과로 단정하지 않으며, 동일 요일·휴일·운영시간·업무 기회 차이를 확인한다. 새 상품·행사 효과는 시행 전후 기간과 비용을 함께 비교한다.

## 직원 동기와 정직한 기록

1. 자동자료는 출처·기간과 함께 읽기 전용으로 보이고, 본인 업무일지는 별도로 작성한다.
2. 차이가 나면 `확인 필요`로 표시한다. 원천 지연, 대리 응대, 예약 변경, 공동 업무 등 사유를 본인이 설명할 수 있어야 한다.
3. 정정은 원기록을 보존하며 변경자·시각·사유·검토자를 남긴다. 원천 다짐 기록과 업무일지 보정은 분리한다.
4. 관리자는 확인·질문·보완을 수행한다. 수치 차이만으로 허위·태만 판정을 내리지 않는다. 본인 열람·설명·이의 제기 절차를 제공한다.
5. 정확한 정정, 조기 문제 보고, 미해결 건 인수인계, 회원 불편 해결, 팀 지원을 구체적으로 인정한다. 기록 건수·매출만으로 경쟁시키거나 정정을 불이익으로 삼지 않는다.
6. 보상은 기여 근거를 검토하는 별도 승인 절차로 설계하고 자동 점수·페널티와 연결하지 않는다.

## 개인정보·기밀 경계: 후속 UI/API 구현 기준

| 사용자 | 기본 노출 | 제한 |
|---|---|---|
| 직원 | 본인 업무와 필요한 운영 안내·비식별 팀 목표 | 회사 총매출·미수금·동료 개인 실적·원장 다운로드 제외 |
| 담당 트레이너 | 본인이 맡은 수업과 필요한 회원 후속 업무 | 다른 담당자 회원목록·연락처 일괄 조회 제외 |
| 센터장/권한 관리자 | 허용된 센터의 운영 집계·정정 검토 | 회사 전체 재무·다른 사업장 원장 제외 |
| 대표/별도 재무 권한 | 필요한 경영 집계·재무 원장 | 접근·다운로드 이력과 최소 권한 유지 |

서버 권한 검사를 먼저 적용하고 화면 숨김만으로 보호하지 않는다. 권한 없는 금액·연락처·회원 원문은 클라이언트에 전달하지 않는다. 보고서·PNG/PDF·공유·AI 입력에도 같은 필터를 적용한다. 소수 인원 집계로 개인이 추정되면 범위를 넓히거나 비공개로 한다. 직원 동의·근무상태·병가 사유를 공개 코칭에 사용하지 않는다.

AI에는 업무에 필요한 비식별 요약만 보낸다. 현재 추가된 서버 측 이메일·연락처·식별번호·인증값 제거는 보조 장치이며 자유서술의 모든 이름·기밀을 자동 탐지한다고 보장하지 않는다. 따라서 외부 전송 전 자료 최소화, 별도 권한 검증, 출력 검토가 필요하다. 원문 회원명·전화번호·상세 매출 파일은 Git에 넣지 않고 접근 제한된 운영 저장소에서 관리한다. 보관기간·삭제 주기·조회/내보내기 감사는 운영 책임자가 정한 정책에 맞춰 후속 구현한다.

## 구현 및 승인 순서

이번 범위: 수집기 로그인/기간/필수값 검증, 재시도 업로더와 API의 잘못된 소스 거부, 프로세스 종료·제한시간·작업 잠금 보완, 오전 재시도·건강 점검, AI 비식별 보조 처리와 공정 코칭 지침.

후속 제품 작업: 권한별 응답·공유 필터 전수 점검 → 출처/품질/기간 카드 → 본인 설명·정정/검토 이력 → 직무별 개인 목표·팀 개선 피드백. 새 DB 필드는 본 스키마와 멱등 마이그레이션을 함께 작성하며 권한·모바일·내보내기 회귀검증 후 배포한다.

운영 지표: 전날 정상자료 확보율·누락 발견까지 시간·복구시간·미해결 요청 처리·정정 처리시간을 우선 본다. 직원 개인의 정직성 점수는 수집하지 않는다. 설계 기준과 자료 사용 목적을 직원에게 알리고 피드백을 받아 조정한다.

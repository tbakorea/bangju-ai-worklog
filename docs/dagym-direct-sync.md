# 다짐 직접 동기화 설정

Bangju AI Worklog은 다짐 운영지표를 서버에서 받아 피트니스 센터운영일지에 반영할 수 있습니다. 직원의 다짐 비밀번호나 브라우저 세션은 저장하지 않으며, 회원 이름·전화번호 같은 개인정보도 앱으로 전달하지 않습니다.

## 필요한 다짐 측 정보

다짐 측에 아래 두 항목을 요청합니다.

- 날짜별 센터 운영 요약을 JSON 또는 CSV로 반환하는 공식 연동 URL
- 해당 URL에서 사용할 서버용 Bearer 토큰

가능하면 센터 식별자도 함께 발급받습니다. 비공개 웹 화면의 세션 쿠키나 개인 계정 비밀번호를 연동용으로 사용하지 않습니다.

## Vercel 환경변수

Production, Preview 환경에 다음 값을 등록합니다.

```text
DAGYM_SYNC_URL=https://공식-연동-주소?date={date}&centerId={centerId}
DAGYM_SYNC_TOKEN=다짐에서_발급한_서버용_토큰
DAGYM_CENTER_ID=센터_식별자
```

`DAGYM_CENTER_ID`는 연동 URL 자체에 센터가 고정되어 있으면 생략할 수 있습니다. `DAGYM_SYNC_URL`은 HTTPS만 허용됩니다.

## 지원 지표

- 오늘 출석
- 신규 등록
- 재등록
- 만료 예정
- PT 예약
- 노쇼/취소
- 락커 만료
- 결제/매출

앱은 위 지표만 추려 저장하며 원본 회원 목록은 저장하지 않습니다. 직접 동기화가 아직 설정되지 않은 동안에는 기존 `다짐 파일 불러오기`와 `붙여넣기 반영`을 계속 사용할 수 있습니다.

## 운영 순서

1. 피트니스 `센터운영일지`에서 날짜를 선택합니다.
2. `다짐 직접 동기화`를 누릅니다.
3. 숫자를 검토하고 필요한 경우 담당자가 수정합니다.
4. 검토가 끝나면 `마감 확정`을 누릅니다.

직접 동기화는 마감을 자동으로 확정하지 않습니다. 운영 담당자의 최종 검토를 남기기 위한 안전장치입니다.

## 현재 확인된 다짐 공식 기능

2026-08-11 다짐매니저의 실제 센터 계정에서 다음을 확인했습니다.

- `매출 > 엑셀 다운로드`: 판매번호, 매출 유형, 판매·결제·환불금액, 결제 담당자, 재등록 여부 포함
- `P.T 수업 관리 > 엑셀 다운로드`: 선택한 수업의 내보내기 제공
- `CEO 리포트`: 신규·유효·만료 회원, 매출, 일정을 일간·주간·월간으로 지정 전화번호에 전송하는 설정형 기능
- `다짐 분석`: 월·분기·년 화면 집계를 제공하지만 별도 내보내기 버튼은 확인되지 않음

현재 공개 API 또는 연동 토큰 발급 화면은 확인되지 않았습니다. 공식 API가 제공되기 전까지는 센터 전용 Mac의 별도 브라우저 프로필을 읽기 전용 수집기로 사용하고, 실패 시 공식 엑셀과 CEO 리포트를 보완 경로로 사용합니다. 수집기는 회원 연락처와 원본 표를 업로드하지 않고 날짜별 합계와 암호화된 PT 일정만 전송합니다.

## CEO 리포트 자동 수신 구조

다짐 CEO 리포트가 지정 전화번호로 도착하면 휴대폰 자동화가 메시지 본문과 기준일만 보안 RPC로 전달합니다. 서버는 출석·신규·재등록·만료·PT 예약·노쇼·락커 만료·매출 숫자만 추출하며, 메시지 원문이나 회원 개인정보는 저장하지 않습니다.

수신 주소:

```text
POST https://zllpfaijahyfppivkxzu.supabase.co/rest/v1/rpc/ingest_dagym_ceo_report
```

필수 헤더는 프로젝트의 공개 `apikey`와 `Content-Type: application/json`입니다. 요청 본문은 다음 형식입니다.

```json
{
  "p_token": "별도로 발급한 64자리 수신 토큰",
  "p_text": "다짐 CEO 리포트 메시지 본문",
  "p_report_date": "2026-08-10"
}
```

수신 토큰은 `select public.rotate_dagym_ceo_ingest_token();`으로 발급하며 휴대폰 자동화에만 저장합니다. 같은 메시지가 여러 번 전달돼도 내용 해시로 중복 저장되지 않습니다. 수신 즉시 센터장 업무일지의 해당 날짜 다짐 집계에 반영하고 다음 날 AI 분석을 다시 생성합니다.

휴대폰 자동화가 아직 설치되지 않았거나 메시지 형식이 바뀌어 핵심 숫자를 찾지 못하면 `partial` 또는 `missing`으로 기록하며, 임의의 값을 만들지 않습니다. 이때 기존 공식 엑셀 불러오기를 보완 경로로 사용합니다.

## 공식 엑셀 가져오기

1. 다짐매니저의 `매출`에서 기간을 선택하고 `엑셀 다운로드`를 누릅니다.
2. Bangju AI Worklog의 피트니스 `센터운영일지`에서 `다짐 파일 불러오기`를 누릅니다.
3. 내려받은 `.xlsx` 파일을 선택합니다.
4. 앱은 현재 열어 둔 업무일지 날짜와 일치하는 결제·환불 행만 골라 집계합니다.
5. 회원 이름·연락처·결제 담당자를 저장하지 않고, 순결제액과 재등록 건수만 저장합니다.
6. 집계 숫자를 확인한 뒤 `마감 확정`을 누릅니다.

환불 행은 매출 유형을 확인해 순결제액에서 차감합니다. 재등록은 판매번호 기준으로 중복을 제거해 계수합니다.

## 매일 새벽 1시 전날 분석

운영 데이터베이스의 `pg_cron`이 매일 `16:00 UTC`(한국시간 다음 날 `01:00`)에 `run_dagym_nightly_analysis()`를 실행합니다. 앱, 브라우저, 다짐 화면을 열어 둘 필요가 없으며 Vercel 로그인이나 배포 환경변수 상태에도 영향을 받지 않습니다.

분석 순서는 다음과 같습니다.

1. 전날 저장된 다짐 운영지표와 피트니스 직원 실행기록을 개인정보 없이 집계합니다.
2. 만료 대비 재등록, 예약 대비 수업기록, 노쇼, 출석 대비 상담행동, 락커 만료를 대조합니다.
3. 긴급·주의·관찰·정상 신호와 오늘 실행 행동, 중기 경영방향을 생성합니다.
4. `dagym_daily_analyses`에 날짜별 결과를 한 건만 저장합니다.
5. 오늘 AI 코칭, 센터 실행지침, 센터 운영보고서의 실제 ChatGPT 코칭 자료에 자동 반영합니다.

데이터베이스에는 다음 마이그레이션을 순서대로 적용합니다.

```text
supabase/migrations/20260811160000_dagym_nightly_analysis.sql
supabase/migrations/20260811170000_dagym_database_cron.sql
```

예약 시각은 `0 16 * * *`이며 한국시간 기준 매일 새벽 1시입니다. 같은 날짜에 다시 실행해도 날짜별 한 건만 갱신하므로 결과가 중복되지 않습니다. `/api/dagym-nightly-analysis`는 운영자가 수동 재실행하거나 외부 예약 서비스를 붙일 때 사용할 수 있는 보조 경로로 유지합니다.

새벽 배치가 일시 실패해도 앱은 오전 1시 이후 첫 로그인 때 동일한 전날 기준으로 로컬 보완 분석을 실행합니다. 전날 자료가 없으면 임의의 실적을 추정하지 않고 `전날 다짐자료 미확인`을 오늘 경영신호로 표시합니다.

## 일일 운영자료·월간 PT 일정 통합 자동 연결

다짐 전용 Chrome에 한 번 로그인한 Mac에서 아래 설치 스크립트를 실행하면 매일 01:05에 작업을 시작하고, 동일 시각 반복 접근을 피하기 위해 0~150분을 임의 대기한 뒤 전날 운영자료와 해당 월 전체 PT 일정을 함께 읽습니다. 수집을 위해 브라우저를 항상 열어둘 필요는 없습니다.

```bash
./scripts/dagym-install-monthly-pt-launchd.sh
```

서버 업로드는 `DAGYM_BROWSER_SYNC_SECRET`가 있으면 기존 전용키를 사용하고, 없으면 승인된 대표·센터장 계정의 짧은 수명 Supabase 인증 토큰으로 검증합니다. Vercel에는 기존 `SUPABASE_SERVICE_ROLE_KEY`, `SUPABASE_ANON_KEY`, `MEMBER_CONTACT_ENCRYPTION_KEY`가 설정되어 있어야 합니다. 회원 이름은 서버에서 AES-256-GCM으로 암호화하며 로컬 감사 JSON에는 이름을 남기지 않습니다.

운영 Mac에서는 평문 `.env.local` 대신 macOS Keychain의 `com.bangju.dagym-sync` 서비스 값을 우선 읽습니다. Vercel의 `DAGYM_BROWSER_SYNC_SECRET`와 이 Keychain 값은 반드시 동일해야 합니다.

Vercel 전용키를 쓸 수 없는 환경에서는 Keychain 서비스 `com.bangju.worklog-sync`, 계정 `j3010@ymail.com`에 업무일지 로그인 암호를 보관합니다. 실행할 때만 인증 토큰을 발급하고 평문 암호와 토큰은 파일이나 로그에 저장하지 않습니다. 서버는 승인 상태와 대표·센터장 권한을 다시 확인한 요청만 허용합니다.

월간 일정 수집기는 다짐 화면의 실제 10건 단위 페이지를 끝까지 순회합니다. 서버 업로드가 실패해도 `work/dagym-monthly-schedule/YYYY-MM.json`에 회원 이름을 제외한 강사별 건수·수집 범위·일정 감사기록을 먼저 남깁니다. 아래 명령은 서버에 전송하지 않고 로그인과 전체 페이지 수집만 점검합니다.

```bash
DAGYM_SYNC_SKIP_JITTER=1 DAGYM_SYNC_MONTHLY_ONLY=1 DAGYM_SYNC_DRY_RUN=1 ./scripts/dagym-monthly-pt-sync.sh
```

일일 수집은 출석, 매출·계약, 회원 현황을 각각 확인하고 월간 PT 일정 DB와 교차 집계합니다. 결과는 `dagym_daily_snapshots`에 날짜별 한 건만 저장하며 `dagym_sync_runs`에는 성공·부분성공·실패와 화면별 수집 건수를 남깁니다. 수집 요청에서는 저장만 끝내고 무거운 분석을 분리해 무료 서버의 실행시간 초과를 막습니다. 전날 분석은 새벽 예약 작업이 담당하며, 앱은 오전 1시 이후 첫 로그인 때 자료 변경을 감지해 같은 날짜 분석을 보완합니다.

지표의 기간 기준도 함께 보관합니다.

- 매출·계약: 해당 월 1일부터 기준일까지의 `월 누계`
- 출석·입장·노쇼: 기준일 하루의 `일간값`
- 회원 현황·만료대상: 수집 시점의 `현재값`
- PT 일정: 해당 월 전체 일정의 `월간 원장`

서로 다른 기간의 값은 비율 계산에서 섞지 않습니다. 예를 들어 월 누계 매출을 당일 출석으로 나눈 객단가는 만들지 않으며, 월 누계 매출은 최신 스냅샷 한 건을 사용하고 날짜별로 재합산하지 않습니다.

다짐 화면 메뉴나 주소가 달라진 경우 로컬 `.env.local`에 아래 주소를 설정하면 코드 수정 없이 교체할 수 있습니다. `{date}`와 `{gymId}`는 실행 시 자동 치환됩니다.

```text
DAGYM_ATTENDANCE_URL=https://www.dagym-manager.com/...{gymId}...{date}
DAGYM_SALES_URL=https://www.dagym-manager.com/...{gymId}...{date}
DAGYM_MEMBERS_URL=https://www.dagym-manager.com/...{gymId}...{date}
```

새 데이터베이스에는 다음 마이그레이션도 적용합니다.

```text
supabase/migrations/20260816090000_dagym_daily_sync_pipeline.sql
supabase/migrations/20260822040000_defer_dagym_daily_analysis.sql
```

동기화한 일정은 강사 이름을 승인된 직원 계정에 연결하고 해당 직원의 시간별일정에 `수강생 이름 + PT 수업`으로 표시합니다. 상태 메뉴는 다음 원칙을 따릅니다.

- `미정`: 예정 일정이며 수업 실적에 포함하지 않음
- `출석`: 수업 실적 1회
- `노쇼`: 예약 시간을 사용한 수업 실적 1회
- `취소`: 수업 실적에서 제외
- `연기`: 수업 실적에서 제외하고 `미정` 또는 새 날짜를 선택

센터운영보고서는 다짐 고유 일정 ID를 기준으로 중복을 제거합니다. 다짐 수업이 들어온 시간대의 기존 수기 PT 문장은 중복 계수하지 않으며, 자동 재계산값과 저장된 직원별 계수를 대조해 차이가 있으면 보고서에 `자동 보정`으로 표시합니다. 담당자가 직접 확정한 검정색 수치는 자동값보다 우선합니다.

## 매출 성장 목표와 데이터 품질

피트니스 운영 목표의 하한은 월 3,000만원, 90일 목표는 5,000만원입니다. 대시보드는 다짐 매출 원장에 실제 값이 들어온 날짜만 집계하고, 누락일을 0원으로 간주하지 않습니다. 자료 수집률이 80% 미만이면 매출 페이스 판정 대신 누락일 동기화를 우선 안내합니다. 충분한 자료가 모이면 현재 월 진도와 남은 일수의 일평균 필요매출을 계산해 상담→체험→등록→재등록 후속업무로 연결합니다. 이는 목표 달성을 보장하는 예측이 아니라 실행 우선순위를 정하는 운영 가드레일입니다.

피트니스 OS의 실행 구조는 세 축으로 고정합니다.

1. `회원·마케팅`: 개인정보 및 광고 수신에 동의한 회원만 만료·재가입 후보로 만들고 상담 배정, 재연락 예약, 발송 이력으로 연결합니다.
2. `직원·성장`: 실제 근무표를 기준으로 출퇴근 완결률과 1% 성장 미션의 수락·실행·회고를 추적합니다. 휴무자는 누락 경고에서 제외합니다.
3. `운영·수익`: PT 예약과 출석/노쇼 결과, 상담, 재등록, 월 누계 매출을 대조해 남은 기간의 일평균 필요매출과 오늘의 담당 행동을 제안합니다.

# 직원 근무 상태·업무일지 참여 관리

## 사용 위치

직원관리 → 근무·참여 → 직원의 상태·참여 변경 → 근무·참여 저장.
퇴사자 보관에서도 상태 변경을 열어 근무로 복귀시킬 수 있다.

- 근무 상태: 근무, 퇴사, 휴직, 병가, 기타 제외.
- 업무일지 참여: 상태에 따라 자동, 참여, 미참여.
- 자동은 기존 상태·시작일·복귀일 규칙을 유지한다. 참여는 휴직·병가 중에도 업무일지를 허용한다. 미참여는 근무 상태에서도 선택한 기간의 업무일지에서 제외한다.
- 퇴사는 참여 선택과 관계없이 보관 처리되며, 근무로 변경해야 복귀한다.
- 적용 시작일, 복귀 예정일, 사유를 저장하며 기존 업무일지와 노무 기록은 삭제하지 않는다.

## 권한 및 저장

대표자 또는 승인된 직원관리(staffManage) 권한 관리자만 저장한다. 운영 관리자·대표 대리 기본 권한을 지원하며 staffManage=false 명시 설정은 거부한다.

별도 set_staff_worklog_participation RPC가 서버에서 권한·상태·참여값·기간·사유를 확인한다. 작성자와 변경시각을 기록하며 승인 상태·로그인 정보·직원 권한은 변경하지 않는다. 일반 직원은 UI와 DB 트리거에서 변경이 차단된다.

직원정보 수정 저장과 근무·참여 저장은 분리한다. 서버 오류나 미적용 마이그레이션을 로컬 성공으로 처리하지 않는다. 과거 업무일지 스냅샷은 현재 근무·참여 상태를 덮어쓰지 않고, 동료/관리자 조회 RPC도 최신 프로필의 상태를 반환한다.

## 운영 DB 적용: 미완료

20261019090000_staff_worklog_participation_management.sql을 운영 DB에 적용해야 한다. Mac 잠금으로 운영 SQL Editor 접근이 불가능해 이번 소스 작업에서는 적용하지 못했다. 기존 직원들의 참여 모드는 기본값 auto로 유지되며, 실제 직원 상태를 일괄 변경하지 않는다.

## 검증

- 정적 QA, 100명×90일 시뮬레이션, git diff --check 통과.
- 신규 기능 전용 Playwright: 휴대폰(390×844), iPad(820×1180), 데스크톱(1440×1000)에서 상태/참여 선택 및 RPC 저장·실패 시 로컬 상태 보존·대표/관리자 허용·일반직원/권한해제 관리자 거부·퇴사 강제 제외·가로 넘침 없음 통과.
- 전체 mobile-browser-qa.sh는 이전부터 실패하던 피트니스 개인 월 누계 검증에서 실패. 전체 통과로 취급하지 않는다.
- 운영 DB의 실제 RPC/트리거 권한 검증은 마이그레이션 적용 후 수행해야 한다.

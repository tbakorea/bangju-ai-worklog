# 다짐 매출 추이와 업무일지 피드백

2026-11-26 구현. 피트니스·방주·비욘드컴퍼니 업무일지와 보고서에 다짐 매출 근거 및 역할별 실행 제안을 표시한다. 승인된 대상 조직 사용자의 인증 요청에만 집계를 반환하며 회원·연락처·거래 식별자는 반환하지 않는다.

## 확인된 매출 (원)

다짐 매출 화면의 `paidPrice`(환불 차감 후 결제액)를 사용한다. 2024-07~2026-10의 28개월 및 비교용 두 기간을 2026-11-26 다시 조회해 상품별 합계와 전체 합계를 대조했다.

| 구간 | 일반·부대 | PT | 합계 |
|---|---:|---:|---:|
| 2026-10 전체 | 9,956,600 | 24,770,000 | 34,726,600 |
| 2026-10 1~25일 | 7,451,100 | 16,390,000 | 23,841,100 |
| 2026-11 1~25일 | 9,309,100 | 7,028,000 | 16,337,100 |
| 같은 기간 차이 | +1,858,000 | -9,362,000 | -7,504,000 |

- 같은 기간 합계 -31.5%, 일반·부대 +24.9%, PT -57.1%.
- 감소의 산술적 기여는 PT -936.2만 원이며 일반·부대 +185.8만 원이 일부 상쇄한다. 이는 인력·상담 등 원인 확정이 아니다.
- 전월 전체 매출 중 PT 비중 71.3%. 전월 전체와 당월 누계의 직접 증감률은 사용하지 않는다.
- 2026년 1~10월 vs 2025년 1~10월: 합계 +11.4%, 일반·부대 -15.8%, PT +53.4%. 합계 개선 속 일반매출 기반의 약화를 별도 확인한다.
- 일반·부대에는 일반 이용권, 일일권, 락커, 운동복 등이 포함된다. PT는 상품명 기준으로 분류한다. 건수는 고객 수나 전환율로 해석하지 않는다.

## 동작

- `api/fitness-revenue-feedback.js`: 인증/승인/대상 조직 확인 후 기존 일일 스냅샷을 읽는다. 조회일 전날까지의 해당 월 최신 검증된 월 누계 한 건만 사용한다. 지연·없음·기간 불일치는 명시한다.
- `api/_lib/fitness-revenue-analysis.cjs`: 전월 같은 날짜, 전월 전체, 월별 추이, 매출 구성 및 장기 신호를 계산한다. 월 누계를 일별로 더하지 않는다. 최근 7일 누락은 연속성 경고로 분리한다.
- 신호 기준은 운영 점검용 규칙: 동일 기간 15% 이상 감소, 전월 PT 비중 65% 이상, 전년 같은 완료월 구간 일반·부대 15% 이상 감소. 통계적 인과 추론이나 개인 평가가 아니다.
- `scripts/dagym-sales-composition.cjs`: 기존 다짐 인증 연결에서 상품별 집계와 전체 집계를 같은 기간으로 조회하고 대조한다. 이름·인증 헤더는 저장하지 않는다. 불일치/실패 시 기존 총매출 수집을 막지 않으며 구성을 추정하지 않는다.
- 기존 스냅샷 `metrics` JSON의 선택 필드 `salesComposition`만 사용한다. 새 컬럼·권한·field_count 변경이나 DB 백필이 없다. schema 파일에 선택 구조를 명시했다.
- 과거 확정 월 집계와 10월 일별 합계는 `fitness-revenue-baseline.cjs`에 보관. 원본 해시·확인 시각을 포함한다. 생성은 `python3 scripts/build-fitness-revenue-baseline.py`; 개인 거래 원본은 커밋하지 않는다.
- 직원은 제안을 선택해야 기존 업무에 추가된다. 대표/동료/센터 전체 읽기 전용과 편집 기간 권한을 유지한다. 일지 데이터에 분석 캐시를 저장하지 않는다.
- 트레이너·센터장·본사에는 PT 상담 단계와 지원 점검, 인포에는 일반매출 개선 흐름 유지, 청결·시설에는 역할 내 회원 경험 개선을 제안한다. 수치로 개인을 비난하거나 강매를 요구하지 않는다.
- 당월 구성은 같은 기준일·합계에 대조된 일일 수집 결과를 우선한다. 과거 대조 자료는 기준일과 합계가 정확히 일치할 때만 보완한다. 미래 날짜에 11월 부진 문구를 자동 반복하지 않는다.

## 검증과 운영

분석/누락/0값/월 전환/기간 대조/권한/민감 필드 제거 테스트 및 일일 수집 API 테스트를 실행한다. 폰(390)·태블릿(820)·PC(1440)에서 표시·업무 추가·중복 방지·동료 읽기 전용을 검사한다. 운영 Mac은 별도 runtime 폴더에서 실행하므로 서버 코드 배포 외에 변경된 수집 스크립트와 신규 helper를 해당 runtime에 반영해야 일별 구성 자동 수집이 활성화된다.

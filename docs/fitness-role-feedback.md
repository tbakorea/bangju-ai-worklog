# 피트니스 보고서의 역할별 개선 피드백

오늘 업무일지 보고서 하단의 `역할별 운영 피드백`은 운영 개선 방향을
본인이 선택할 수 있는 실행 한 가지와 연결한다. 운영 분석에서 도출한
재등록·초기 정착·문의 후속·수업 이행·이용 불편 해소를 역할별로 구체화한다.
재무 원장의 숫자를 직원 목표나 실적 평가로 전환하지 않는다.

## 역할과 흐름

- 센터장: 만료 상담 담당·확인일, 팀 지원, 원장 차이 확인.
- 인포·상담: 이용 목적·방문 시간, 동의에 따른 만료 상담, 다음 안내.
- 트레이너: 실제 수업 결과, 회원의 이용 경험, 다음 운동 계획.
- 홍보: 대상·회원 효익·문의 경로, 확인된 반응, 소재 재사용.
- 시설·청결: 한 구역·한 요청의 점검, 처리 확인, 인수인계.
- 미확인 역할: 담당 가능한 업무의 기준과 지원 확인. 센터장으로 추정하지 않는다.

최근 30일 중 최근 20개 보고일의 본인 피드백 실행기록을 읽는다.
미완료면 기존 실행을 이어가고, 완료 응답 다음 보고일에는 다음 작은 실행을 제안한다.
같은 날 완료 기록을 반복 저장해도 단계가 계속 증가하지 않는다.
지원·보류·설명은 다음 조치를 확인하는 자료이며 감점이나 징계 근거가 아니다.
관리자 확인 없는 완료 응답을 실제 개선 효과로 표현하지 않는다.
다른 역할·미래 날짜의 기록은 단계 결정에서 제외한다.
직원이 제안을 수정한 경우 `custom` 실행으로 남겨 기존 표준 과제 완료로 오인하지 않는다.

## 저장·권한

기존 `worklog_coaching_followups.coaching_snapshot` JSON에
`fitnessFeedback: {version, roleKey, stepKey, stage}`만 추가한다.
스키마·정책·권한을 추가하거나 바꾸지 않는다. DB 마이그레이션은 필요 없다.
직원은 본인 실행을 저장하고, 기존 권한을 가진 대표·관리자가 후속 검토한다.
동료의 보고서를 읽을 수 있다는 사실만으로 동료 실행기록을 조회·편집하지 않는다.
로그아웃·사용자 전환 시 이력 캐시를 초기화하며, 이전 세션의 비동기 응답은 버린다.
읽기 실패는 이전 기록 확인 전으로 표시한다. 날짜 경과만으로 진전시키지 않는다.

## AI·보고서

브라우저와 API에서 동일한 허용 목록을 적용한다. 새 코칭 입력은 역할·단계·표준 실행,
업무 분류와 건수로 한정한다. 회원·직원 이름, 연락처, 업무일지 원문,
회사 매출·급여·이자·인센티브, 기존 경영 분석 원문은 전달하지 않는다.
API가 실패해도 역할별 실행과 확인 기준은 표시된다.
보고서의 단계·다음 실행·확인 기준은 규칙이 결정하고 AI는 실무 팁만 보완한다.
코칭의 확인·실행·지원 요청, 결과·관리자 검토는 기존 메뉴를 사용한다.
이력·AI 비동기 갱신이 작성 중인 실행·지원 설명을 덮어쓰지 않는다.
이미지·PDF·공유에도 같은 네 항목을 사용하며, 현재 보고서만 출력 공간을 보완한다.
기존 과거 보고서의 코칭 미표시 동작은 유지한다.


브라우저 검증은 합성 자료만 사용하며 390px·820px·1440px에서 이력 재조회,
지원/완료 분기, 본인·동료·위임 조회, 오류 처리, 원문 차단, JSON 저장 메타데이터,
작성 중 입력 보존, 보고서 미리보기와 내보내기 잘림을 점검한다.

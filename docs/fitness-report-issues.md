# 피트니스 운영 이슈 → 수신자 본인 업무일지 보고서

- 수신자: 기존 계정 매핑에 고정된 김성민·이소미·김경희. 이메일과 승인된 서버 프로필 이름을 함께 검증한다. 직급 변경이나 동명이인으로 수신 범위를 확장하지 않는다.
- 본인 일반 업무일지의 보고서 하단 `비욘드 피트니스 · 운영 확인 이슈`에 표시한다. 보고서를 열 때 다시 조회한다. 별도 메일·푸시 발송은 없다.
- 자료: 승인된 피트니스 소속 직원의 선택일 `ownerWorklog.fitnessOps.specialReport` 최신 일일 저장본, 선택일 분석에 저장된 전날 다짐 분석. 다른 날짜 자료로 대체하지 않는다.
- 직원 원문은 서버에서 안전·시설·고객응대·정산·기타 확인 항목으로만 분류한다. 표현의 존재를 알릴 뿐 사고/민원 발생·미해결 사실로 확정하지 않는다. 동일 분류는 합친다.
- 다짐은 날짜가 맞는 자료의 누락, 예약결과 및 락커 후속 확인만 전달한다. 기간·누락에 영향을 받는 PT 차이/만료 대비 재등록 비율/상담 부족은 전달하지 않는다. 기록 차이로 성실성·인사 불이익을 판단하지 않는다.
- 회원명·연락처·직원 원문·상세 금액·수업 명단은 응답에 포함하지 않는다. AI 입력에도 추가하지 않는다. 기존 RLS나 타 직원 원문 열람 권한을 변경하지 않는다.
- 로그인 계정/날짜별 메모리 캐시(60초), 로그아웃 시 삭제. 다른 직원 열람 화면에는 노출하지 않는다. 서버 재조회가 원본이며 업무일지에 복제 저장하지 않는다. 기존 DB 구조를 사용하므로 마이그레이션 없음.
- 일부 자료 누락/조회 실패를 정상 또는 이슈 없음으로 표시하지 않는다. 실패해도 업무일지 입력·저장은 가능하다.
- 이미지·PDF·인쇄·공유·텍스트 복사에 같은 내용을 반영한다. 출력 전 조회를 기다리며 실패 문구도 보존한다.
- 운영 의존성: 기존 서버의 SUPABASE_SERVICE_ROLE_KEY. 클라이언트로 보내지 않는다. 없으면 503 및 조회 실패 표시.
